pygmix.com ヒーロー見直し — 参照ブリーフと方向の提案

2026-09-06 作成／きっかけ: 「舞台スケッチをこの倍くらいまで大きくしたい。そろそろそもそものデザインの見直しも必要かもしれません」

★実装済み・公開待ち 本人承認（2026-09-06「OKです すすめてください」）を受けて実装済み。 下の結果は実際の画面（localhost:3000）から撮影したもの。公開はご本人のデプロイ操作待ち。

1. なぜ見直しが要るか（実測）

「倍」＝約 640×336px。1440×900 のヒーローに、その大きさが入る場所はありません。

置き場所の候補結果 実測
円の上・中央画面外（y −145〜191）
円の下・中央画面外＋流れる皿と208回衝突
左半分／右半分／中央中央の円と重なる＋皿と208回衝突

円が y205〜595（390px）を占め、その周りを皿が回っているため。1.5倍（500×262）でも円の上には入りません（空きは185px）。置き場所の調整では解けない＝構成の問題です。

ついでに見つかった不具合

  • 不具合 ヒーローの WORKS の飛び先 #activities が存在しません。押しても何も起きません。
  • 不足 自動で回るコンテンツに aria-live の指定がありません（下の参照3を参照）。
  • 実測 皿の画像は初回表示で全部読みます（public/visuals/ 計 1.1MB）。遅延読み込みが効かない構造です。

2. 参照（実際に開いて確認したもの）

① 東京芸術劇場 — 催しが多い場所が、トップで何を先に出すか

https://www.geigeki.jp/（2026-09-06 確認）

確認した事実 トップの最上段が「公演・イベント Pick up」（画像付き6件）。次が「本日の催し」、その後に利用案内、ジャーナル、施設紹介。装飾的なキャッチコピーは無し。

採る: 催しが多い場所ほど、トップの一番上は「いま見てほしいもの」に使われている。文言は機能的（何が・いつ）。
採らない: 6件並べる形。pygmixは「いま1つを大きく」が目的なので、件数を増やすと目的に反する。

② Panic — 製品を多く持つ工房が、1つを押すときの順番

https://panic.com/（2026-09-06 確認）

確認した事実 ヒーローは社名＋具体的な一行「We code apps, publish games, and make Playdate.」。その直後に1つだけの新着（Prompt 3.5）。そのあとに事業区分ごとの製品一覧。

採る: 「素性を一行で言う → いま推す1つ → 全体の目録」という順番。押しの1つは独立した帯を持ち、素性の領域に押し込まれていない。
採らない: 製品を均等に並べる姿勢。pygmixは今回「1つを大きく」が要件。

③ W3C ARIA Authoring Practices — 自動で回るコンテンツの要件

https://www.w3.org/WAI/ARIA/apg/patterns/carousel/（2026-09-06 確認）

確認した事実 自動回転するなら「停止・再開ボタン」が必須。キーボードのフォーカスが入ったら止まる。マウスが乗っている間は止まる。回転中は aria-live="off"、止まっているときは polite。

現状の実測 停止ボタン ✔（「コンベアを止める」）／ホバーで停止 ✔／フォーカスで停止 ✔（実際に paused になることを確認）／皿11枚すべてキーボード到達可 ✔／aria-live のみ未指定。

採る: いまの作りは要件をほぼ満たしている。コンベアは残してよいという判断の根拠になる。足りない aria-live だけ足す。

参照は分析のためのもので、レイアウトや文言をそのまま持ち込むことはしません。①②はページ内容の並び順を実際に読んで確認した事実、③は仕様書の記述です。

3. 提案する方向

理由の連鎖
初見の人は「これは誰で、何がある場所か」を数秒で知りたい（利用者と場面） → 素性は一行で伝わればよく、画面の全部を使う必要はない（要件） → 芸劇もPanicも、トップの上段は「いま見てほしいもの」に使い、押しの1つは独立した帯を持っていた（参照の根拠） → 素性の領域を縦に詰め、その下にPICKUPの帯を作る（採る原則） → コンベアと円は残す。pygmix固有の核であり、W3Cの要件も満たしているため（実装）
① 素性の帯（いまのヒーローを縦に詰める）
PYGMIXの円＋コンベア＋門。高さ 100vh → 約62vh。円とレールは比率のまま縮む。
1440×900 で 558px。レール（504px）が収まる下限。
② PICKUP の帯（新設）
全幅。640×336 の面の画像＋機能的な一行＋行き先。高さ 約38vh（1440×900 で342px）。
スマホ390pxでは 351×184。いまの148pxの約2.4倍。
③ ライブラリ（いまのまま）
作品一覧。WORKS の飛び先が無い問題は、ここへ繋ぐか、区分を作って解消する。

あわせて直すこと

  • WORKS の飛び先（いま #activities で存在しない）
  • 自動回転に aria-live を指定（回転中 off／停止中 polite）
  • ヒーローが短くなるぶん、初回に読む画像の量を見直す余地が出る（現状1.1MB）

変えないこと

  • 回転寿司の比喩（皿・コンベア・入口/出口の門）＝pygmix固有の核
  • 配色・書体・極小モノスペースの札・対角だけ極端な角丸
  • 「真面目に、ふざける。」とPYGMIXのロゴ

4. 気になる点（先に言っておきます）

  • ヒーローが全画面でなくなります。コンベアの見える面積が減り、没入感は下がります。これが受け入れられないなら、②を「1画面目の下」に置く（スクロールが要る）案に切り替えます。
  • 640×336 はいまのOGカード画像の原寸です。これ以上大きくすると画像が粗くなるので、拡大するなら元画像を作り直す必要があります。
