# pygmix.com デザイントークンシート — ヒーロー見直し＋PICKUP
最終更新 2026-09-06／対象: `app/OrbitHero.tsx`（識別の帯）・`app/page.tsx` の `.pickup`（新設）

このシートが正。実装で値を変えたくなったら、コードより先にここを直す。
前版（円の中／円の外・上に埋め込んだPICKUP）は本人指示「もう少し大きくしたら大体の
イメージはOK。そろそろそもそものデザインの見直しも必要かもしれません」により**廃止**。
このシートは新しい構成（識別の帯を縦に詰め、PICKUPを独立セクション化）のみを記録する。

## 0. 設計メモ（design-policy.md の5つの問い）

1. **誰が・どの場面で**: pygmix.com のトップに来た人が、最初の数秒で「いま何を見てほしいか」を受け取る場面。
2. **どんな気分に**: 識別（PYGMIXは何者か）を短く受け取ったあと、「いま押しているのはこれ」を実物大に近い写真で見て、押したくなること。
3. **固有の核**: ヒーローは**回転寿司の比喩**（皿・コンベア・入口/出口の門）でできている。これは識別の帯の核であり続ける。**ただし「いま推す1つ」は、この比喩の中に押し込める必要はない** —（参照: 東京芸術劇場・Panicとも、トップ上段の押しは独立した帯を持っていた。docs/2026-09-06_hero-redesign-brief）。
4. **踏襲するもの / 意図的に外すもの**
   - 踏襲: 回転寿司の比喩（皿・コンベア・門）はそのまま。配色・書体・極小モノスペース（6〜8px・字間0.13〜0.18em）・「対角だけ極端な角丸」（`10px 64px 10px 10px` 等）。
   - 外す: PICKUPを流れる皿やコンベアの内側に埋め込むこと。円のサイズを膨らませて専用の場所を作ること（前版はこれで424pxまで広げていたが、640×336には届かなかった）。
5. **守る機能条件**: タップ44px以上／コントラスト4.5:1以上／`prefers-reduced-motion` で動きを止める（既存のグローバル指定で担保）／画像は同梱済みの640×336を使い、追加の読み込みを増やさない／W3C ARIA APG カルーセル要件（停止ボタン・ホバー/フォーカスで停止・`aria-live`）。

## 1. なぜ見直したか（実測・2026-09-06）

「舞台スケッチをこの倍くらいまで大きくしたい」＝約640×336px。1440×900 の旧ヒーロー
（100vh・円390px）にこの大きさが入る場所は無かった（円の上＝画面外、円の下・左右＝流れる
皿と208回衝突・円と重なる、を実測済み）。置き場所の調整では解けず、構成を変える必要があった。

## 3. 識別の帯（`.orbit-hero`）の再調整値

円・コンベアは比率を保ったまま、新しい高さに収まるよう実測で縮めた。

| 変数 | 旧値（100vh想定） | 新値 | 根拠 |
|---|---|---|---|
| `min-height`（base, >900px） | `max(780px, 100svh)` | `max(560px, 62svh)` | 1440×900で560px |
| `--route-y` | `clamp(235px, 28vh, 275px)` | `clamp(120px, 15vh, 150px)` | 新ヒーロー高560pxに、コンベアが門・隅ラベル・ヒント文と重ならず収まる値を実測 |
| `--route-y-soft` | `clamp(155px, 19vh, 185px)` | `clamp(80px, 10vh, 100px)` | route-y と同じ縮小比（15/28≒0.536）を適用 |
| `--route-x` | `clamp(340px, 34vw, 480px)` | `clamp(280px, 30vw, 400px)` | 縦を大きく詰めたので横も穏やかに詰め、扁平になりすぎるのを防ぐ |

| `min-height`（≤900px, 固定値だった） | `780px` | `500px` | 同じ縮小比（560/900）を適用 |
| `min-height`（≤600px, 固定値だった） | `820px` | `480px` | 同上 |

## 8. 追記 2026-09-06（空きスペースを詰める・PICKUPの文字拡大・タップ面の是正）

### 8.1 ★一度やり直した。ここが今回いちばん重要な記録

本人指示「回転寿司が広すぎるのでつめて舞台スケッチをよせましょう」を、**横幅が広すぎる**と
読み違えて route-x 一式を約15%縮め、さらに「画面外でのクリッピング」を不具合とみなして
出入りの不透明度キーフレームまで書き換えた。

本人の意図は**「回転すしの形は変えることなく空いているスペースを詰めたかった」**だった。
すべて元へ戻した（route-x / route-x-soft / route-x-inner / route-out の3ブレークポイント、
および `@keyframes conveyor-route` の 3% / 97% の不透明度）。

**学び2点。**

1. **「広い」は横幅とは限らない。** レイアウトの指摘では、寸法を変える前に
   「余白が広い」のか「要素そのものが大きい」のかを実測で切り分ける。
2. **皿が画面外へはみ出すのは不具合ではなく設計。** 入口 IN / 出口 OUT の門をくぐって
   画面外から現れ、画面外へ去るのがこの画面の演出そのもの。計測上の「クリッピング」を
   機械的に潰さない。

### 8.2 空きスペースの正体（実測）

回転寿司の本体（皿＋中央の円）は、`--route-y` が `clamp(120px, 15vh, 150px)`、
`--card-height` が `clamp(126px, 10.9vw, 148px)` と**どちらも clamp の上限で頭打ちになる**ため、
大きい画面ではどれだけ広げても **477px で固定**される。
それなのにヒーローの高さは `max(560px, 62svh)` と画面の高さに比例させていた。結果、
**縦に長い表示ほど空きだけが増えていた。**

| 画面 | ヒーロー高（前） | 本体 | 空き |
|---|---|---|---|
| 1440×900 | 560px | 477px | 98px |
| 1728×1117 | 693px | 477px | 215px |
| 1937×1919 | 1190px | 477px | **712px＝ヒーローの60%** |

**直し方**: `min-height` から svh 依存を撤去し、本体が収まる固定値にする。
**回転寿司の形（route-x / route-y）には一切触れていない。**

★最初 560px にしたら「ちょっと狭すぎますね」との判断（同日）。本体477pxに対し
上下の余白が計98pxしか残らず、隅ラベルへ16px・ヒント文へ5px、皿が掠めていた。
**620px**（タブレット幅は 500→**540px**）へ。

| 画面 | ヒーロー高 | 本体 | 余白 上/下 | 余白率 |
|---|---|---|---|---|
| 1440×900 | 620px | 462px | 56 / 102 | 25% |
| 1440×1200・1937×1919・2560×1440 | 620px | 477px | 56 / 87 | 23% |
| 768×1024 | 540px | 423px | 46 / 71 | 22% |
| 390×844 | 480px | 368px | 52 / 61 | 23% |

余白率が全幅で22〜25%にそろい、**隅ラベル・ヒントへの掠めはどの画面でも0px**になった。
**PICKUPの開始位置は画面の高さによらず固定**（1937×1919 では 1190px → 620px）。

## 9. 追記 2026-09-06（皿の中にコンテンツ・中央を横長の楕円で後ろへ・間隔の均一化）

本人指示3件。互いに影響するので **②中央の楕円 → ③皿の中身 → ①間隔** の順で作った
（皿の大きさが決まらないと間隔を決められないため）。

### 9.1 ③ 皿の中にコンテンツを収めた

**原因**: カードは角丸の長方形（224×148）、皿は楕円（240×164）。長方形の角は必ず楕円の外に出る
（角(112,74)は皿の内側の楕円(115,77)に対し (112/115)²+(74/77)²=**1.87>1**・実測）。

| 項目 | 前 | 後 |
|---|---|---|
| `.orbit-card` の角丸 | `52px 8px 52px 8px`（偶数枚は `8px 62px 8px 62px`） | **`50%`（皿と同じ楕円）** |
| 皿 `.orbit-item::before` | `card + 16px` | **`card × 1.2`**（縁が見える） |
| `.orbit-card img` | `height: calc(100% - 43px)` | `height: 100%`（楕円いっぱい） |
| `.orbit-caption` | 左右いっぱいの帯 | **中央寄せの札**（幅70%・`bottom:16%`・角丸999px） |
| `.orbit-caption small`（配信元） | 表示 | **非表示** |
| `.orbit-plate`（アイコン面） | 高さ `100% - 43px`・横並び | 高さ100%・**縦積み中央**・下に34%の余白 |

★札の幅を70%にした根拠: 楕円の弦は下へ行くほど狭く、下から16%の高さでカード幅の**73%**（実測）。
★配信元を消した根拠: 6pxでも41字＝**164px**あり、札の157pxを超えて切れていた
（`stagesketch-try.juggler-arata.workers.dev` で実測）。同じ情報は下のライブラリに載っている。

### 9.2 ② 中央を横長の楕円にして皿の後ろへ

`aspect-ratio: 1` → **`1.62`**、`width: clamp(310px,29vw,390px)` → **`clamp(360px,41vw,580px)`**、
`z-index: 12` → **`2`**（皿は4、レールは0）。

★**停止ボタンが皿に常時100%覆われて押せなくなっていた**（実測）。楕円の中に置いていたためで、
楕円を後ろへ回した副作用。`.orbit-toggle` を楕円の外・ヒーロー左下へ出し `z-index:15` に。
ロゴとナビは0%（覆われない）を実測で確認済み。

### 9.3 ① 皿の間隔を均一にした

**原因**: 区切りが等間隔の%だったため、経路の長さと%が対応せず速さが **12.3〜32.0 px/%** とばらついていた。

**直し方**: 各区切りの%を「区間の長さ ÷（皿の進行方向の張り出し ＋ 目標のすき間）」に比例させる。
皿は楕円なので張り出しは `2√((A·ux)²+(B·uy)²)`。加えて画面外の助走を **カード幅×4**（下限あり）に。

★これだけでは**直角に曲がる左上・右上の角**が -71px まで詰まる。隣り合う皿の直線距離が
経路長より短くなるため（経路の縦は135pxしかないのに皿は178px）。実測と完全に一致する模型
（1440×900で -99/-26/-20 を再現）を作り、区切りの%を数値最適化して補正した。

| | 前 | 後 |
|---|---|---|
| すき間（1440×900） | -135〜+22px 相当 | **-38〜+20px（中央 -10）** |
| むら | 157px | **58px** |
| 同時に見える枚数 | 7.6枚 | 7.9枚 |

キーフレーム: `0 / 12 / 28.23 / 29.22 / 32.67 / 39.26 / 42.93 / 50 / 57.07 / 60.74 / 67.33 / 70.78 / 71.77 / 88 / 100`。

★数値は1440×900で最適化した固定値。CSSのキーフレーム%は画面幅に追従できないため、
他の幅では経路の比率が変わりむらが残る（768×1024で154px）。作り直すときは同じ模型で解き直すこと。
